About

PRエンジニアリングという提案

PRエンジニアリングは、AIだけで完結する仕組みではありません。人とAIが一緒に手を動かし、互いに進化していく（共進化）ための、どかんが提案する進め方です。

PRを、一人の経験から、
進化し続ける仕組みへ。

  1. 01

    DESIGN

    事業の目標から逆算し、その会社ならではのPRを設計する。

  2. 02

    IMPLEMENT

    PRの知見をSkill化し、人とAIが協働できる仕組みとして実装する。

  3. 03

    EVOLVE

    人の判断とAIの能力を循環させ、変化に合わせて共進化させる。

PRエンジニアリング

名PR Engineering

企業と社会の関係をつくるPRの仕組みを設計し、運用し、AIも含めて最適化する。

Human Communication × AI Optimization

  1. DESIGN｜自社ならではのPRの仕組みを設計する事業の目標や課題、組織、社会との関係性を踏まえ、成果につながるPRのあり方を設計する。一般的な「PRの型」を当てはめるのではなく、その会社だからこそ機能するPRの仕組みをつくる。
  2. IMPLEMENT｜人とAIで動く仕組みにするPRの戦略や実務に蓄積された知見を、AIが再現できる手順（Skill）へと分解・構造化。人が担うべき判断とAIに任せられる仕事を組み合わせ、日々のPR活動の中で実際に使える仕組みとして実装する。
  3. EVOLVE｜人とAIが共進化する仕組みへ一度つくって終わるのではなく、時代の変化、会社の状況、取り組むテーマに応じて仕組みそのものを柔軟に変えていく。人の判断や経験がAIに蓄積され、AIが生み出した時間によって人はより創造的な仕事へ。人とAIが互いに学びながら、PRの仕組みそのものを進化させ続ける。

PR会社の支援も、PRエンジニアリングも、目指すのは事業の目標から逆算した広報の成果です。違いは、その成果を生み出す方法と、ノウハウが蓄積される場所にあります。

Approach

事業の目標から逆算して、
AIを広報に組み込む。

PRエンジニアリングは、ツールを入れることから始めません。広報で達成したい事業の目標や、解決したい課題を最初に定め、そこから逆算してAIエージェントの使い方を設計します。業種や商材を問わず使える、2つの進め方があります。

Model case A

目標達成型

例：これまで届いていなかった層に、ブランドを「自分に合うもの」と感じてもらい、ファンと継続的な購入・利用を増やしたい

  1. 目標を決めるターゲットに起こしてほしい行動や、つくりたい状態を定める
  2. ゴールの姿をそろえるブランドの想起につながるSNSでの発話やメディア露出が、自然に生まれている状態を具体的にすり合わせる
  3. 測る指標を決めるメディア露出件数、リリースの閲覧数、SNSでの言及数、フォロワーや反応の数、noteの閲覧数など
  4. AIの使い方を設計する環境の把握 → PR・オウンド・UGC（生活者の投稿）施策の運用方針づくりとAIによる半自動化 → Skill化して継続的に改善
  5. 小さく試して、運用へ小さな検証から始め、効果を確かめながら日々の運用に移していく

Model case B

課題解決型

例：発信の遅れや対応漏れ、認知不足、ネガティブな評判、人手不足といった課題を解消したい

  1. 課題を決める現場で起きている課題を洗い出し、優先して取り組むものを定める
  2. 解決の姿をそろえる「何がどう変われば解決と言えるか」を言葉にして、関係者の認識をそろえる
  3. 測る指標を決める対応にかかる時間、対応漏れの件数、関係者の満足度、ネガティブな言及や問い合わせ件数の推移など
  4. AIの使い方を設計する原因とボトルネックの特定 → 業務フローの再設計とAIによる半自動化 → Skill化して継続的に改善
  5. 運用に定着させる定型の作業はAIで型にし、判断や関係づくりが必要な場面に人の時間を振り向ける

※業種・商材を問わない進め方の例です。実際の導入事例ではありません。

広報業務の手順のうち、AIで対応できる割合

AIが担うのは、下書き・調査・集計といった手順の一部です。最終的な確認と判断、社内外の関係構築、一次情報の取得は人が行う前提で試算しています。AIが力を発揮しやすいのは、測定やSNS・Webの運用といった定型的な業務です。一方で、危機管理や経営広報、メディアリレーションズのように、状況判断や関係づくりが問われる領域では、割合が低くなっています。定型的な業務をAIに任せることで、人は社内外の関係構築や一次情報の取得、攻めの広報により多くの時間を使えるようになります。

FAQ

よくあるご質問

広報担当が1名だけでも依頼できますか？

はい、可能です。むしろ少人数の広報体制こそ、仕組みで回す効果が大きいと考えています。担当者の方が日常業務の中で無理なく使えるよう設計します。

成果はどのように確認できますか？

導入の最初に、事業の目標または課題と、それを測る指標（メディア露出件数、SNSでの言及数、対応にかかる時間など）を御社と一緒に決めます。毎月のレポートで進捗を確認しながら、Skillや施策を改善していきます。

まだClaudeを契約していません。

問題ありません。ご状況に合ったプランの選び方も、ヒアリングの中でご説明します。契約自体は、御社とAnthropic社（または正規代理店）との間で行っていただきます。

社内の情報をAIに入れても大丈夫でしょうか？

基盤構築の段階で、入力してよい情報の範囲や確認手順をガバナンスとして定めます。公開前には必ず御社担当者が承認するフローを組み込みます。

プレスリリースの作成代行とは何が違いますか？

作成代行は、専門家が原稿を仕上げる支援です。PRエンジニアリングは、リリースや企画を生み出す手順そのものを御社のAI環境に実装し、社内で使い続けられる状態にする支援です。目的に応じて、組み合わせてご活用いただけます。

費用はどのくらいかかりますか？

ご支援の範囲や期間によって異なります。プラン構成はサービス資料でご案内していますので、まずは資料をご覧ください。
