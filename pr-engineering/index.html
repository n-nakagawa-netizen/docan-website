About

PRエンジニアリングという提案

PRエンジニアリングは、AIだけで完結する仕組みではありません。人とAIが一緒に手を動かし、互いに進化していく（共進化）ための、どかんが提案する進め方です。

PRを、一人の経験から、
進化し続ける仕組みへ。

  1. 01

    DESIGN

    事業の目標から逆算し、その会社ならではのPRを設計する。

  2. 02

    IMPLEMENT

    PRの判断基準をSkillに、御社の事業・ブランド・過去の発信をナレッジとして組み込み、人とAIが協働できる仕組みとして実装する。

  3. 03

    EVOLVE

    成果や反応に加え、メディアの関心や社内の検討内容もAIに戻し、人の判断とAIの能力を循環させ、変化に合わせて共進化させる。

PRエンジニアリング

名PR Engineering

企業と社会の関係をつくるPRの仕組みを設計し、運用し、AIも含めて最適化する。

Human Communication × AI Optimization

  1. DESIGN自社ならではのPRの仕組みを設計する事業の目標や課題、組織、社会との関係性を踏まえ、その会社だからこそ機能するPRのあり方を設計する。
  2. IMPLEMENT人とAIで動く仕組みにするPRの知見をAIが再現できる手順（Skill）へ分解し、人が担う判断とAIに任せる仕事を組み合わせて実装する。
  3. EVOLVE人とAIが共進化する仕組みへ会社の状況や取り組むテーマに応じて仕組みを変え続ける。人の判断がAIに蓄積され、AIが生んだ時間で人は創造的な仕事へ。

Approach

事業の目標から逆算して、
AIを広報に組み込む。

PRエンジニアリングは、ツールを入れることから始めません。広報で達成したい事業の目標や、解決したい課題を最初に定め、そこから逆算してAIエージェントの使い方を設計します。業種や商材を問わず使える、2つの進め方があります。

Model case A

目標達成型

例：これまで届いていなかった層に、ブランドを「自分に合うもの」と感じてもらい、ファンと継続的な購入・利用を増やしたい

  1. 目標とゴールの姿をそろえるターゲットに起こしてほしい行動と、実現したい状態を具体的にすり合わせる
  2. 業務を棚卸しし、現在地を知る14領域・118業務の枠組みで、今の広報業務とAIに任せられる範囲を洗い出す
  3. 測る指標を決めるメディア露出件数、SNSでの言及数、フォロワーや反応の数など
  4. AIの使い方を設計し、運用へ施策の運用方針づくりとAIによる半自動化 → Skill化 → 小さく試して日々の運用に移す

Model case B

課題解決型

例：発信の遅れや対応漏れ、認知不足、ネガティブな評判、人手不足といった課題を解消したい

  1. 課題と解決の姿をそろえる優先して取り組む課題と、「何がどう変われば解決と言えるか」を関係者ですり合わせる
  2. 業務を棚卸しし、現在地を知る14領域・118業務の枠組みで、今の広報業務とAIに任せられる範囲を洗い出す
  3. 測る指標を決める対応にかかる時間、対応漏れの件数、ネガティブな言及の推移など
  4. AIの使い方を設計し、運用へボトルネックの特定 → 業務フローの再設計とAIによる半自動化 → Skill化して定着させる

※業種・商材を問わない進め方の例です。実際の導入事例ではありません。

広報業務にかかる時間を、AIでどれだけ減らせるか

AIが担うのは、下書き・調査・集計といった工程です。最終的な確認と判断、社内外の関係構築、一次情報の取得は人が行う前提で、AIの出力に人が手を入れる時間も見込んで試算しています。測定やSNS・Webの運用のような定型業務では削減率が高く、経営広報やメディアリレーションズのように交渉と関係づくりが中心の領域では低くなります。

全体平均32%

  1. 効果測定・モニタリング6業務60%
  2. SNS10業務40%
  3. オウンドメディア・Web8業務39%
  4. プレスリリース・情報発信8業務35%
  5. PR戦略・企画9業務33%
  6. 経営広報・IR9業務24%
  7. メディアリレーションズ12業務23%

出典：どかん調べ（試算）。広報部門の業務を14の領域・計118業務に分け、業務ごとに「AIに任せられる工程の割合 × 手戻り係数」で作業時間の削減率を試算し、集計したもの。手戻り係数は、収集・集計など人の確認が軽い作業は0.85、原稿や資料の下書きは0.65、企画・戦略など人の判断の比重が大きいものは0.55、交渉・現場対応が中心のものは0.5として、5%刻みに丸めた。実測値ではなく、2026年時点の一般的な水準を想定した推定。全体平均は14領域・118業務すべての平均。上の一覧は7領域の抜粋。

FAQ

よくあるご質問

広報担当が1名だけでも依頼できますか？

はい、可能です。むしろ少人数の広報体制こそ、仕組みで回す効果が大きいと考えています。担当者の方が日常業務の中で無理なく使えるよう設計します。

社内にエンジニアがいなくても使えますか？

はい。Claude Code・Claude Coworkのどちらもデスクトップアプリがあり、日々の業務は自然言語の指示だけで進められます。ファイルの整理や資料づくり、毎日・毎週の定型業務まで任せられるので、広報担当者の方がそのまま日常業務で使えます。

成果はどのように確認できますか？

導入の最初に、事業の目標または課題と、それを測る指標（メディア露出件数、SNSでの言及数、対応にかかる時間など）を御社と一緒に決めます。毎月のレポートで進捗を確認しながら、Skillや施策を改善していきます。

社内の情報をAIに入れても大丈夫でしょうか？

基盤構築の段階で、入力してよい情報の範囲や確認手順をガバナンスとして定めます。公開前には必ず御社担当者が承認するフローを組み込みます。
